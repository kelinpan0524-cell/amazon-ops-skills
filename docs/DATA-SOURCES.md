# 数据源接入：领星 MCP / 卖家精灵 MCP / 亚马逊 SP-API

> 查证日期：2026-11-04。三句话先记住：**卖家精灵看外面的市场（选品/关键词/竞品），领星看自己的店铺（销量/利润/库存/广告），SP-API 管自动化和官方原始数据。** 三者互补不重复，不是三个都要开——按本文最后的优先级来。

| 想干什么 | 用什么 |
| --- | --- |
| 「我们店卖得怎样、哪个广告亏了、库存撑几天」 | 领星 MCP |
| 「这个词一个月多少搜索量、类目竞争度、竞品销量」 | 卖家精灵 MCP |
| 自动调价 / 批量上下架 / 官方原始明细入库 | SP-API（+ 独立的 Ads API 管广告自动化） |

---

## 第 1 步：领星 MCP（本周就配；已付 ERP 费用，零额外成本）

**它给什么**：自己 11 个店铺的经营数据——Listing、订单、FBA 库存、补货建议、利润报表、广告活动/关键词/搜索词报告、退货分析。日常问答 80% 靠它。限流每秒 1 次，够日常问，别做批量拉数。

**安全要点（先读）**：领星 MCP 的数据权限 = 生成密钥那个领星账号在 ERP 里的权限。**建议专门用一个只有查看权限的账号去生成密钥**，AI 天生只能看不能改——与本仓库「写操作永不自动」铁律配套。

**管理员开通（10 分钟）**：
1. 登录领星 ERP → 【业务配置】→【开放接口】→【MCP】→ 启用（付费版才有）。
2. 【AI 助手 → MCP】页面：点「复制 JSON」（拿地址）和「复制密钥」（拿 X-Mcp-Key）。

**每人配置（5 分钟）**：在自己的 AI 工具（ZCode/Claude/豆包等）里添加 MCP 服务器：
- 类型：**Streamable HTTP**（流式 HTTP）
- 地址：`https://openmcp.lingxing.com/mcp-servers/lingxing-mcp`
- 请求头：`X-Mcp-Key: <你的密钥>`

**验证**：问一句「查一下最近 7 天 XX 店铺的销量」，能出数即成功。

**凭证规矩**：密钥只放本机 AI 工具的配置文件或 `~/.zshrc`，**永不进 git 仓库、不发群里**；泄露了在 ERP【管理 MCP】页面重新生成即可作废旧钥。

## 第 2 步：卖家精灵 MCP（可选；确认要做选品/关键词再买）

**它给什么**：市场数据——关键词搜索量与竞争度（500 万+ 关键词库）、竞品销量估算（2 亿+ ASIN）、类目趋势、出单关键词反查。这些是亚马逊不对外公开的，官方渠道拿不到。

**先不买的理由**：AI 助手只回答经营类问题的话，领星全覆盖。观察一个月运营实际问 AI 的问题里有多少是「市场情报类」，多再买（MCP 套餐月付，随时可加可停；有网页版账号的先查现有套餐是否已含 MCP 额度，别重复买）。购买页：<https://www.sellersprite.com/mcp-purchase>

**买了之后（5 分钟）**：
1. 在[数据开放平台](https://open.sellersprite.com)创建应用拿密钥（「我的密钥」页）。
2. AI 工具添加 MCP：类型 Streamable HTTP，地址 `https://mcp.sellersprite.com/mcp`，请求头 `secret-key: <密钥>`。
3. 验证：「挖掘关键词 control arm 的搜索量和竞争度」。
4. 省额度技巧：查询默认 `size=10`（每次少拉点），显著降消耗。

## 第 3 步：亚马逊 SP-API（有自动化需求再上；**注册审核要 30–47 天，想走这条路今天就提交**）

**它给什么**：官方原始数据（订单/报表/财务/FBA 库存/Listings）+ 写操作能力（改 Listing、同步库存）。广告自动化是**另一套独立的 Amazon Ads API**，不在 SP-API 里。

**关键认知**：
- **不是每个卖家自己弄一套**。公司用主账号注册一个「私有应用开发者」，**11 个店铺统一授权给这一个应用**，凭证集中管理。
- 前提：注册开发者的账号是**专业销售计划**（Professional，$39.99/月）；私有应用**免费**，不上架应用市场。
- 2023 年 10 月起**不再需要 AWS/IAM**，只要 LWA 三件套（client_id / client_secret / refresh_token）。
- refresh token **长期有效**（只有后台手动解除授权或关店才失效）；access token 1 小时一换，程序自动刷新。
- 巴西站（BR）好消息：和美加墨同属北美区，同一套凭证通吃 US/CA/MX/BR。
- 限流：令牌桶（常见每秒 1–5 次），官方建议用定时报表（6–12 小时一次）代替高频轮询。

**管理员流程**：
1. **今天可做**：主账号卖家后台 → 应用与服务 → 开发者平台（Developer Central）→ 注册「私有应用开发者」→ 等审核（30–47 天，不勾 PII 审核更快）。
2. 审核通过后新建 SP-API 角色应用，记下 **LWA client_id / client_secret / app_id**。
3. 自家账号：开发者平台直接点 Authorize 拿第一个 refresh token。
4. 其余 10 个店铺：把授权链接（app_id + 回调地址拼出）发给各店管理员 → 对方登录点同意 → **5 分钟内**把回跳的授权码（spapi_oauth_code）交回 → 换该店 refresh token。每店一个 token，按「店铺-站点」编号。
5. 凭证保管：全部进密码管理器或服务器环境变量；`.env` 必须在 `.gitignore` 里，**绝不进仓库**。

**验证**：用一个 token 调一次 Orders 接口（带 BR 站 marketplace ID `A2Q3Y263D00KWC` 试试），能返回订单即通。

## 优先级建议（10 人团队、年销 1600 万 USD 规模）

1. **领星 MCP——本周**：零成本、半天上线、覆盖 80% 日常。
2. **卖家精灵 MCP——按需**：确认选品/关键词是 AI 助手职责后再买。
3. **SP-API——现在提交注册慢慢等**；真正上线等有自动化需求（自动调价/数据自动入库/嫌领星限流）且有专人维护时。

## 与本仓库的配合

- 本仓库 `data/normalized/` 四张表的数据来源是**领星后台手工导出**（`scripts/import_lingxing.py`）。配好领星 MCP 后，AI 可以直接回答即时问题；报表技能仍以归一化表为准（口径统一、可复算）。
- 两者不冲突：MCP 适合「问一句答一句」，仓库报表适合「每天定时跑、异常才叫人、数字可追溯」。将来若要消灭手工导出，再评估「SP-API/领星开放平台定时拉数 → 自动归一化」的管道。

## 卖家精灵自带的 4 个官方技能 vs 我们的技能（2026-11-04 实测）

**卖家精灵 MCP 随客户端提供 4 个官方技能**（ZCode 技能面板可见，本地无可读文件，属客户端侧注册）：

| 官方技能 | 干什么 |
| --- | --- |
| 卖家精灵-亚马逊运营助手 | 店铺/ASIN 运营分析问答 |
| 卖家精灵-亚马逊选品助手 | 类目/选品评估 |
| 卖家精灵-亚马逊商品文案助手 | 标题/五点/描述生成 |
| 卖家精灵-评论痛点分析助手 | 单 ASIN 1-3 星评论痛点提炼 |

**结论：选品、文案、评论分析这三块不用自己造轮子，直接用官方技能。**

官方技能与我们的技能是两种形态，互补不冲突：

| | 卖家精灵官方技能 | 我们的仓库技能 |
| --- | --- | --- |
| 触发 | 你问一句，它答一次 | 定时自动跑（Mac Mini） |
| 数据 | 卖家精灵的市场估算数据 | 领星真实经营数据 + 卖家精灵（竞品） |
| 产出 | 对话式回答 | **存档 HTML 报告 + 飞书归档 + 预警退出码** |
| 强项 | 临时深度调研、文案生成 | 每天固定看数、异常才叫人、数字可追溯 |

**分工建议**：
- 日常经营（我店卖得怎样、哪个店跌了、库存撑几天）→ 我们的 `amz-store-daily` / `amz-week-month-review` / `amz-alert-center`；
- 临时调研（这个类目值不值得进、这个词搜索量多少、竞品为什么起量）→ 直接问官方技能；
- 竞品周监控（固定名单、只报变化、要留痕）→ 我们的 `amz-competitor-watch`（它用卖家精灵底层数据，但会存档+比对+出报告）。

**额度注意**：官方技能和我们的脚本**共用同一个卖家精灵套餐额度**（按次计费）。
日常别用脚本狂拉（我们的脚本已做省额度设计：`--no-fetch` 用缓存、只拉清单内 ASIN）。
