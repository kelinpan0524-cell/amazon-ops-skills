# amz-inventory-alert

> 库存/断货预警：按可售天数给店铺与 SKU 分档（急/关注/注意/正常），带补货建议与目标对照，每天定时跑。

| | |
| --- | --- |
| 类型 | 每日监控（自动） |
| 运行 | 每天 06:00 自动 |
| 有脚本 | 是 |

## 数据源

inventory_daily（领星 get_fba_stock_list，FBA 可售/在途/预留/不可售）+ sales_daily（近 7 天销量）

## 逻辑链路（这是怎么算出来的）

① 取数：FBA 库存快照按 (店,SKU,ASIN) 取最新一天；销量按 SKU 聚合近 7 天

② 算日均：近 7 天销量 ÷ 7（不是只看昨天——单日波动会误判）

③ 算可售天数：FBA 可售 ÷ 日均；日均为 0 的归「零动销」档，不算断货

④ 分档：急 <7 天（当天处理）/ 关注 7-14 天（本周补）/ 注意 14-21 天（排计划）/ 正常 ≥21 天

⑤ 低频过滤（关键防误报）：日均 <0.5 件的 SKU 即使可售 0 天也只归「低频」档，不报急——实测 47 个『急』里大半是一年卖 36 件的僵尸 SKU，全报会让人麻木

⑥ 层级选择：优先 SKU 级（断货是一个个 SKU 断的），没有 inventory_daily 时退店级兜底

⑦ KPI 用中位数不用加权平均：加权 158 天但 9 个 SKU 已 0 天——平均数会骗人，中位数 33.7 天才反映真实

## 为什么这样设计 / 阈值依据

分档 7/14/21 天：断货掉排名要 6-8 周恢复（平台共识），7 天是补货最后窗口；低频线 0.5 件/天是实测僵尸 SKU 的分界。
