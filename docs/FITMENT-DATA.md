# 汽配适配数据：007vin / ACES / PIES / PCfitment 怎么用

> 调研日期 2026-11-04。事实部分标注来源；**具体接口参数需登录后核对**（我只在未登录状态查了公开页）。

## 一句话结论

三条线各管一段，**不重复也不替代**：

| 工具/标准 | 管什么 | 在我们流程里的位置 |
| --- | --- | --- |
| **007vin（零零汽）** | 中国视角的车型/VIN/OE 查询 API | **校验**：我们写的 OE 号、车型适配是不是真的 |
| **ACES / PIES（Auto Care 标准）** | 美国行业标准：ACES 管"适配哪些车"，PIES 管"产品是什么" | **对齐**：亚马逊 Part Finder 认的就是 ACES 数据 |
| **PCfitment** | SaaS 工具：把 Excel/OE/竞品号转成标准 ACES/PIES XML，并提交亚马逊/eBay/Walmart | **提交**：真要把 fitment 灌进亚马逊时用 |

**关键认知（决定要不要投入）**：亚马逊前台有 **Part Finder**（按年款-品牌-车型筛配件）。
ACES 数据准确 → 买家能搜到、少退货；数据错/缺 → 商品在 Part Finder 里查不到，等于把流量让给对手。
汽配类目退货率高的第一原因就是「适配不符」，所以**适配数据是钱，不是技术细节**。

## 一、007vin（零零汽）：拿它做 OE 校验

**是什么**：杭州云汽配配科技有限公司旗下汽配数据服务（`007vin.com` / API 域名 `api.007vin.com`），
按 VIN 或车型锁定配件，对外提供**车架号查询、车型查询、零件号查询、OE 查询**四类接口；
宣称覆盖约 93% 车辆品牌、900 万+ 零配件数据，服务约 4 万行业用户（含电商平台、汽修 SaaS、汽配 ERP）。

**我们能拿它干什么**（按性价比排序）：

1. **OE 号真实性校验**（最高价值）：`sku_master.csv` 里的 `oe_number` 逐个查，
   查不到或对不上的打标——这直接喂给 `amz-listing-audit` 的 fitment 命门检查；
2. **车型适配反查**：给一个 OE 号，反查它到底适配哪些年款/车型，用来补 `year_from/year_to`；
3. **VIN 解码**（客服场景）：客户报 VIN，确认该车到底装哪个件，减少发错货。

**接入方式**：API 需要商务开通拿密钥（`api.007vin.com` 文档页需登录）。
你说 ego 服务器已登录——那可以用 ego-browser 走网页端做**批量比对**（不用等 API 开通），
路径：登录态浏览器 → 逐个 OE 查询 → 导出结果表 → 回写 `data/raw/fitment-check/`。

**写法约定**（防翻车）：
- 查询结果**落 raw 存档**，不进 git（`data/` 已 gitignore）；
- 只做「校验/补全」，**不自动改 Listing**——改 fitment 是业务写，人工确认；
- 三方数据都标来源与查询日期（007vin / Auto Care 版本号），报告里不许混写。

## 二、ACES / PIES：亚马逊认的标准

- **ACES**（Aftermarket Catalog Exchange Standard）当前 **5.0 版**，XML 格式，描述"零件适配哪些车"；
- **PIES**（Product Information Exchange Standard）描述产品属性（尺寸/材质/包装…）；
- 配套参考库：**VCdb**（车辆）、**Qdb**（限定符）、**PCdb**（零件分类）、**PAdb**（零件属性），
  通常按年付费订阅；
- **Brand ID（AAIA Brand Code）** 必须申请（Auto Care VIP 门户），亚马逊要求品牌代码与零件号精确匹配；
- **Auto Care 已于 2025-01 向全行业开放 ACES/PIES/IPO 参考库 API**（JSON、支持每日增量），
  这是"自己写脚本对版本"的正路，不用手工下 XML 包。

**我们要不要自己造 ACES XML？** 现阶段**不要**。理由：ACES 的坑在参考库版本（VCdb 每年更新）
和 Brand 注册流程，自己维护成本远高于收益。我们的做法是：
**用 007vin 校验准确性 → 用 PCfitment 这类工具产出/提交标准文件 → 我们只做前端的质量检查与报告**。

## 三、PCfitment：真要提交时用它

**是什么**：美国/中国都有站的 SaaS（`pcfitment.com` / `pcfitment.cn`），
把原始数据（Excel、PDF、OE 号、竞品零件号）转成 ACES/PIES 标准 XML，
并自动提交到 **Amazon / eBay / Walmart / Shopify / BigCommerce / SEMA Data Co-op**；
提供 YMM 查询工具、Auto Care 月更提醒，且是**亚马逊授权的 ACES 适配数据供应商**
（可代表卖家向亚马逊提交）。定价参考：约 **$15/月起**（单品牌 ≤150 SKU），有 14 天试用。

**什么时候值得买**：当我们要**批量修正亚马逊上的 fitment**（不是几十个 SKU，而是成百上千）时。
现在（11 个店铺、874 个在售 ASIN）规模还没到，先用 007vin 做校验、人工改关键 SKU 更划算。

## 四、落地顺序（建议）

| 阶段 | 做什么 | 成本 | 产出 |
| --- | --- | --- | --- |
| **现在** | 用 007vin（ego 登录态）抽查 `sku_master` 的 OE 号与车型，出「适配准确率」基线 | 0（已有登录） | 知道我们 fitment 到底有多差 |
| **2 周内** | `amz-fitment-check` 技能固化：抽样规则、比对逻辑、报告模板 | 开发 0.5 天 | 每月自动跑一次适配体检 |
| **3 个月内** | 若准确率低且影响退货 → 评估 PCfitment 试用 14 天，把重点 SKU 的 ACES 提交规范化 | $15/月起 | 亚马逊 Part Finder 覆盖提升 |
| **半年后** | 视规模评估订阅 Auto Care 参考库 API，自建 ACES 版本对账 | 年费 | 完全自主可控 |

**红线提醒**：
- 适配数据可以写品牌名/车型名（文字侧允许，见 `metrics.brand_logo_hold` 的 text 模式）；
- **但图片里绝不能出现车标**（image 模式 HOLD）——两条规则别混；
- OE 号是别人家的商标信息，用于**适配声明**是行业惯例，用于**暗示原厂**（如"OEM Genuine"）是违规；
- 报告里写清「数据来源 + 查询日期 + 覆盖率」，不许把抽查结论说成全量结论。
