# 选品调研

**回答一个问题：这个类目/细分值不值得进。** 不是"这个词搜索量多少"（那是 `amz-keyword-intel`）。


## 交互协议（主动调用时：先问清，再执行）

本技能是**主动式**技能。被调用时不要直接闷头跑脚本：先核对下面的前置信息，
缺哪项就**用带选项的问题**一次问清（一次最多 3 个问题，能合并就合并），拿到答案再执行。

| 前置信息 | 为什么需要 | 选项 / 默认值 |
|---|---|---|
| 目标市场/站点 | 决定数据口径与币种 | 选项：美国站（默认）/ 英国站 / 德国站 / 其他（需说明） |
| 类目或关键词 | 没有方向就无法圈候选池 | 自由输入；若用户说「你帮我选」，先给 3 个基于现有店铺类目的方向让其挑 |
| 售价带与预算 | 决定资金占用与毛利空间 | 选项：$15–30 / $30–60 / $60+；默认 $15–60 |
| 筛选阈值 | 月销、竞争度、评论数门槛 | 默认：月销 ≥300、头部评论 <500、非垄断品牌；可改 |
| 数据时效 | 是否调卖家精灵实时数据 | 默认实时；密钥缺失时说明并改用已有数据，不编数 |

多轮对话规则：
1. 用户后续补充或修改口径时，以**最新一轮**为准，并复述确认关键参数（范围/对象/阈值）。
2. 信息齐全后先用一句话复述「我要用什么对象 + 什么时间窗 + 什么阈值 + 输出什么」，再动手。
3. 缺数据/缺密钥时直说并给替代路径，**不编数**；外部写操作（发消息、写外部表格、改广告）必须显式确认。
4. 用户只想快速要结果时，可直接采用上表默认值，但要在开头列出所用默认值。

## 五步流程（按顺序，每步用哪个接口写清楚了）

### 第 1 步：定位类目
```
category.search(keyword="control arm", marketplace="US")
```
拿到类目节点**完整路径**（形如 `1055398:284507:...`）。
**必须用完整路径**——深层节点传短 ID 会静默查空，看起来像"这个类目没数据"。

### 第 2 步：市场容量
```
category.report.detail(categoryId="完整路径", dataRange="LAST_30_DAYS")
```
看：商品总数、总销售额、平均客单价、平均评论数、Top10 品牌占比。

### 判读门槛（用我们自己的类目实测校准过，2026-11-04）

**先说结论：网上流传的那套门槛（商品数<3000、Top3<40%）在汽配类目完全不适用。**
我们实测 Control Arms 类目：商品数 **27,539**、Top3 品牌占 **96.6%**、
但平均评论只有 **28** 条——我们自己也在这个类目里做。

所以按那套标准，连我们自己都不该进。**重新定**：

| 指标 | 能进 | 谨慎 | 别进 | 为什么 |
| --- | --- | --- | --- | --- |
| **平均评论数** | **<50** | 50-200 | **>500** | 最硬的指标：决定新品要攒多久才能竞争 |
| **新品销量占比** | **>10%** | 5-10% | **<3%** | 新人在进 = 门开着；<3% = 进不去 |
| **平均月销量** | >20 件 | 10-20 件 | <10 件 | 长尾太薄的类目赚不到钱（我们实测 17 件） |
| 月总销售额 | >$500K | $100K-500K | <$100K | 盘子要够大，但这条容易看错（见下） |
| ~~商品数~~ | **不做判断** | | | 汽配每个车型/年款一个 SKU，天然上万，无参考价值 |
| ~~品牌集中度~~ | **不做否决** | | | 汽配 Top3 占 96% 是常态，长尾照样有空间 |

### 为什么这两条以前的指标不能用

**商品数**：汽配的 SKU 结构决定的。一个控制臂要覆盖 20 个车型 × 5 个年款 = 100 个 SKU，
27,539 个商品不代表"竞争激烈"，只代表"车型多"。

**品牌集中度**：Top3 占 96.6% 看着吓人，但那 96.6% 是**销售额**集中度，
不是"没有长尾"。我们这种月销 30 万的店在 27,539 个商品里排不进 Top3，
但活得好好的——**长尾有空间，只是上不了头部**。

### 真正该问自己的三个问题（比看数据重要）

1. **这个车型的 fitment 数据我们有吗**？没有车型数据，市场再好也做不了
2. **平均评论 28 条**说明客户不挑评论——你只要 30 条评论就能跟头部站在同一起跑线
3. **新品占比 4%** 说明新人能进但难上量——想清楚是做长尾还是冲头部

### 第 3 步：竞争格局
```
category.top.list(categoryId="路径", dimension="brand", topN=10)
category.stats.list(categoryId="路径", ...)   # 按规模/集中度筛
```
看头部是谁、集中度多少、有没有中国卖家（`sellerNation` 过滤）。

### 第 4 步：需求趋势（会不会过时）
```
category.demand.report(categoryId="路径", days=365)
category.demand.trend(categoryId="路径")        # 24 个月搜索量趋势
```
看：搜索量在涨还是跌、有没有明显季节性（汽配通常 Q4 旺）。

**趋势向下 + 集中度高 = 别进**，哪怕现在销售额不错。

### 第 5 步：新品成功率（最容易被忽略）
```
category.stats.list(categoryId="路径", newProportion={...}, ...)
```
看新品（3 个月内上架）占多少销售额。**新品占比 <5% 说明这个类目新人进不去**。

## 结论怎么给

必须给三选一，不许模糊：

| 结论 | 条件 |
| --- | --- |
| **GO** | 平均评论 <50 **且** 新品占比 >10% **且** 平均月销 >20 件 **且** 我们有这个车型的 fitment 数据 |
| **CAUTION** | 平均评论 50-200，或新品占比 5-10%——能做但要靠差异化（fitment 更全 / 装得上） |
| **AVOID** | 平均评论 >500 **或** 新品占比 <3% **或** 平均月销 <10 件——这三条任一条就够呛 |

**注意：不再用「商品数」和「品牌集中度」做否决**——汽配类目这两个指标天然畸形，
按它们判会把所有汽配类目都否掉，包括我们自己正在赚钱的。

**结论必须带数字依据**，不能只说"竞争激烈"。

## 跟其他技能的分工

| 想问什么 | 用哪个 |
| --- | --- |
| 这个类目能不能进 | **本技能** |
| 这个词搜索量多少、相关词有哪些 | `amz-keyword-intel` |
| 这个竞品的差评在哪（找差异化点） | `amz-review-insight` |
| 我现有 ASIN 的流量结构 | `amz-traffic-diagnose` |

**推荐组合**：先本技能判 GO，再用 `amz-review-insight` 看头部品的差评找切入点，最后用 `amz-keyword-intel` 定词。

## 成本

全流程约 8-15 次卖家精灵调用（取决于翻页深度）。**按次计费，别对同一个类目反复跑**——
第一次跑完把结论记下来，下次先看记录。

## 口径与边界

1. 所有搜索量/销售额都是**估算值**（卖家精灵模型推算），只能做相对判断
2. `category.stats.list` 是**三方样本口径**（默认取销量前 100），跟亚马逊官方"选品指南针"的商品总数不是一回事
3. 汽配类目有 fitment 门槛：**你自己有没有车型数据**比市场数据更重要——没数据就算 GO 也做不了
4. 本技能**只出判断，不下单、不采购**
