# 跨境合规、税务与物流清关门禁

> 本技能由 `doubao-ecommerce-compliance-tax-logistics` 最小适配而来，适配点仅：
> 1. 技能名改为 `amz-compliance-tax-logistics`，交接目标改为本仓库内既有技能；
> 2. 顶部加本仓库契约：**只读、source-first、缺数写 `needs_data`、禁止无证据结论、不执行任何写操作**；
> 3. references 内容原样保留，未删改。
>
> 适用对象是**整个汽配类目**（不限于控制臂、衬套、悬置、球头、拉杆——这几类只是当前主营示例，不构成适用边界；车标门禁同样覆盖全部汽配），所有结论必须能指回一次取数或官方页面。

分层边界：官方一手证据 / 候选事实 → 抽字段与跨文件对账 → 风险判断规则 → 门禁结论（DIAGNOSE / DRAFT / HOLD / NO-GO / CONDITIONAL）→ 人工审批 → 发货/入仓/上线等外部执行（仓库不执行）。

## 用途

围绕「这个 SKU / 这批货能不能卖、能不能发、能不能入 FBA」做跨境门禁，把三条相互关联的工作流合成一个判断：

1. **合规与产品准入**：禁限售、认证、标签、宣传宣称、安全、危险品、平台政策风险。
2. **税务与 IP 风险**：VAT/GST/Sales Tax、OSS/IOSS、Nexus、Marketplace Facilitator、商标、专利、版权、品牌授权、灰产、假货风险。
3. **清关与物流履约**：HS 编码、关税、到岸成本、Commercial Invoice、COO、CN22/CN23、DDP/DDU、FBA/FBM、海外仓、3PL、库存/履约约束、清关文件。

用 references 路由细节，不把任务拆成多个技能。**没有官方一手证据时不给放行**：当场核不到就标 `unverified` / `needs_data`。

## 何时使用 / 不使用

**使用：**

- 判断某 SKU / 某国站点能否销售、能否发货、能否入 FBA / 海外仓。
- 需要查禁限售、强制认证与标签、VAT/GST/Sales Tax/Nexus、Marketplace Facilitator 代收、HS/关税/DDP-DDU、危险品与清关文件对账。

**不使用：**

- 不替代律师/税务师/报关行给出最终法律、税务、清关专业结论；那是人工与专业顾问的事。
- 不执行任何发货、入仓、上线、付费等外部写操作。
- 不把第三方工具、同行 listing、Accio/WorkBuddy 输出当成政策权威；未核验前都是候选。
- 字段或官方证据缺失时，不硬给“能卖/没税/HS 就是 X”的结论。

## 最小输入

- **必填**：目标国家/地区 + 平台；产品名、材质、成分/用途、目标用户、电池/液体/粉末/食品/化妆品/医疗/儿童/电子等风险属性、品牌/IP 元素。
- **HS/关税/清关**：原产国、目的国、产品描述、材质/用途、申报货值、币种、数量，最好有候选 HS 或供应商规格。
- **税务**：卖家主体、平台/独立站、发货地/仓位置、客户目的地、销量/单数、B2B/B2C、税号、平台是否代收代缴。
- **履约**：平台、履约方式、重量/尺寸、包装、库存量、售速、退货预期、危险品状态、目标服务水平。
- **中国进口**：中国进口商/收货人、贸易方式、原产国、发货国、SKU 级产品属性、候选 HS、成交方式、发票、装箱单、CCC/标准/标签状态、IP 授权链、目的地销售渠道。
- **evidence-bound 文件任务**：输入文件清单与来源层级；聊天记录、旧草稿、供应商说法、报价在没被显式指定为权威前都只是线索。
- 缺以上任一字段：直接写缺什么，**不猜重量、日期、税率、认证覆盖、文件状态**。

## 运行与输出

本技能是**纯提示词/门禁技能，无脚本**，不调用任何平台、ERP、广告、清关写接口。输出固定为状态之一：

- `DIAGNOSE`：诊断中，列出关键事实、阻断与缺的证据。
- `DRAFT`：草稿（含生成的 Excel/CSV/Word），公式或总额未自检通过前不得叫 final。
- `HOLD` / `NO-GO`：存在用户闸门或准入/IP/税务阻断，列清关闭所需证据、owner、核验路径。
- `CONDITIONAL`：条件放行，条件未满足前仍不得发。
- 证据缺失：`needs_data`；官方页面当场核不到：`unverified`（附核验 owner/path）。

复杂多 SKU/多国/文件任务先按 `references/cross-file-reconciliation.md` 建来源清单与对账台账，再从同一事实模型出所有交付物；交付前跑文字/Excel/CSV/Word 的内部一致性检查。按任务只路由需要的 references（见「高级规则」）。

## 示例

以占位说明，不写死任何税率、HS 或货值：

- 问「`<SKU>` 从中国发美国 FBA，能不能入仓？」→ 若缺重量、申报货值、是否带电池等字段，输出 `needs_data` 清单，而不是“可以发”。
- 问「图片上能不能放个丰田标？」→ 命中车标硬规则，输出 `NO-GO`，要求移除/替换后重审；但若文案只是 “fits Toyota Camry 2018”，不因本规则自动阻断，转既有商标证据审核。
- 问「这票货 VAT 怎么交？」→ 未核验到目标国/平台代收规则前，输出 `unverified` + 官方核验路径，不给具体税率结论。

## 失败降级

- 缺目标国家/产品关键字段：给通用清单并追问，不下针对性结论。
- 官方规则/税率/HS/认证/危险品分类当场核不到：标 `unverified` + 核验 owner/path，不当成结论。
- **一个 SKU 的文件状态（UN38.3、SDS、CCC、授权、审批等）不得抄到另一个 SKU**，除非证据显式覆盖。
- 用户定义闸门（含 A9 车标）未关闭：不许建议试发、分批发、DAP/DDP 发、海外仓转仓、FBA 入仓或 listing 上线，也不许自行放宽成“关几个 P1 就行”。
- 生成交付物有公式错、总额不一致、箱规数学错：报 `DRAFT` 或修好再交，不交 final。
- 图片/Fitment 卡是否含车标无法自动判定（本技能无图像识别能力）：输出 `needs_human_review`，不默认“图里没标”就放行。

## 数据质量限制

- 平台规则、税率、HS、认证、危险品类、低价值进口规则必须绑到官方/一手来源路径 + 核验日期；第三方工具、同行 listing、公开页面在核验前都是候选。
- 税务结论必须按路线与渠道分开：平台仓、3PL、FBA、本地仓、直邮、独立站销售**不能塌成一个税务结论**。
- 本技能不做利润/毛利判定；涉及成本毛利时沿用仓库“领星毛利/成本未校准”口径，不输出已校准利润结论。
- 不假装图像识别：对图片与 Fitment 卡的车标语义一律走人工复核。

## 人工确认边界

- 发货、FBA/海外仓入仓、海外仓转仓、DDP/DAP 执行、listing 上线、付费推广等任何外部动作由人批准。
- **用户定义闸门高于任何通用 playbook**：提示词里的放行/持有/P0/P1、停发条件优先执行。
- **A9 车标硬规则（适用于全部汽配）**：文案、图片、Fitment 卡、Listing 或发布建议中一旦出现整车厂品牌**图形标识本身**（奔驰三叉星、BMW 蓝白圆标、丰田三椭圆、福特蓝椭圆等），判 `NO-GO`，必须移除/替换后重审；YMM/OE/“for Toyota Camry”等适配**文字不是车标**，不自动阻断。
- 最终法律、税务、IP、清关、HS、关税、平台政策结论，须由卖家或专业顾问确认。
- 向 Listing/图片/广告/库存等下游交接时，必须显式附带车标门禁（见「交接规则」）。

## 高级规则与工作流

以下为该技能保留的完整门禁与路由细则，属于标准契约之后的高级内容，不随统一格式删减。

### 仓库契约（最高优先级）

- **只读**：本技能只输出 `DIAGNOSE` / `DRAFT` / `HOLD` / `NO-GO` / `CONDITIONAL`，不调用任何平台、ERP、广告、清关写接口。
- **source-first**：平台规则、税率、HS 编码、认证、危险品类、低价值进口规则，必须绑到官方或一手来源路径 + 核验日期。当场核不到就标 `unverified`，给出核验 owner/path，不当成结论说。
- **needs_data**：缺字段就写缺，不估、不凑区间。重量、日期、税率、认证覆盖、文件状态一律不许猜。
- **外部候选值 ≠ 公司校准值**：第三方工具、同行 listing、Accio/WorkBuddy 输出只是候选，未核验前不许写进 `profiles/` 或当成阈值。
- **【用户硬规则 A9】车标 = 发布阻断项**。车标指汽车整车厂的**品牌图形标识本身**（emblem/badge，如奔驰三叉星、BMW 蓝白圆标、丰田三椭圆、福特蓝椭圆等图形）。文案、图片、Fitment 适配卡、Listing、或发布建议中一旦出现车标图形，**一律不得给可发布结论**，输出 `HOLD`/`NO-GO`，必须移除或替换后再复核。本规则是用户定义的发布闸门，**不需要外部来源才能生效**。
  - **不要扩大化**：YMM（年款/品牌/车型）文字、OE 号、"for Toyota Camry"、"fits 2018 Honda Accord" 这类适配文字**不是**车标，仍按既有商标/证据规则审核，**不因本规则自动阻断**。
  - **图像无识别能力时保留人工复核**：本技能不做图像识别；对图片/Fitment 卡是否含车标无法自动判定时，输出 `needs_human_review`，不许默认"图里没标"就放行。

### 核心工作流（Core Workflow）

1. **选执行模式**。普通问题用 advisory 模式。一旦请求里出现表格、发票、装箱单、SKU 主数据、报价、多附件、数值模型、要生成 Excel/CSV/Word、或对上一次交付物的更新，就切 evidence-bound file 模式。组合任务必须先把证据事实和算清，再给合规/物流结论。
   - **先核验再下结论**。任何关于平台规则、税率、注册门槛、强制认证、HS/关税、危险品运输、进口规则、官方备案状态的关键判断，必须绑到官方或一手来源路径 + 核验日期。当场核不到就标 `unverified`，给核验 owner/path，不要当成最终结论。
2. **判断业务路径**：产品准入、禁限售、认证/标签、宣称、IP/品牌授权、税务、HS/关税、清关文件、DDP/DDU、履约/海外仓、中国进口，或组合式"能不能卖并发这个货"。
3. **抽关键贸易字段**：只抽回答所需的字段——产品名、材质、用途、平台、目标国家/站点、原产国、发货地、仓位置、卖家主体、货值、重量、尺寸、品牌/IP 元素、履约方式、已提供证据。复杂或文件重的工作用 `references/response-reference-patterns.md` 当可选推理辅助，不是强制输出模板。**永远不许把发货地/出口国当成原产国**。
4. **文件先对账再分析**。evidence-bound file 模式下读 `references/cross-file-reconciliation.md`。先建来源清单、归一化 SKU 证据台账、差异表、计算台账、控制总额表，再写结论。
5. **跑准入与限制预筛**。优化物流之前，先看每个 SKU 是否禁售、受限、需认证、危险品、侵权、宣称敏感、或证据缺失被卡。读 `references/risk-taxonomy.md`。**不许因为产品相似就把一个 SKU 的文件状态套到另一个 SKU**。
6. **选官方来源路径**。读 `references/source-map.md`。中国大陆作为进口国时再读 `references/china-import-playbook.md`。优先政府海关、税务、平台政策中心、Seller Center、商标/专利库、承运商、一手卖家证据。
7. **只路由到需要的 references**：税务/IP 读 `references/tax-ip-playbooks.md`；HS/关税/清关/DDP/DAP/IOR 读 `references/hs-tariff-customs-workflow.md`；FBA/FBM/海外仓/3PL 读 `references/fulfillment-playbooks.md`。电池、无线、皮肤接触、儿童、电子、食品/化妆品/液体/粉末/化学品等高危品读 `references/high-risk-product-check-trees.md`。不加载与本任务无关的通用风险材料。
8. **把事实、假设、计算、未知分开记**。每个关键事实记来源。公开页面、Accio/WorkBuddy、第三方工具、同行行为在核验前都是候选。缺值就留缺，**不许在用户没显式要求假设场景时猜重量、日期、税率、认证覆盖、文件状态**。
9. **分配风险与证据状态**。用 `references/risk-taxonomy.md`。用户给了 P0/P1/观察项定义时用用户的。按 SKU 和受影响批次记风险，连同关闭所需的确切证据。
   - **尊重用户闸门**。提示词定义了放行闸门、停发条件、P0/P1 关闭规则、"X 之前不许发"，这些规则高于任何通用 playbook。**不许自己放宽成"8 个 P1 关 6 个就行"，也不许在任一用户定义的阻断闸门未关闭时建议试发、分批发、DAP/DDP 发、海外仓转仓、FBA 入仓、或 listing 上线**。
10. **从同一个事实模型出交付物**。任何文字回答、Excel、CSV、Word 都从同一份对账后的事实和计算台账出。文件/公式纪律用 `references/document-checklists.md`。`references/response-reference-patterns.md` 只在表格或结构化交接更清楚时用。
11. **过最终闸门**。从明细重算控制总额，跨交付物比总额和状态，校验表结构和公式，核心总额或 SKU 状态不一致就停。闸门没过不许给最终放行建议或最终数值答案。
    - **生成文件先自检再报完成**。Excel/CSV/Word 交付前扫 `#NAME?`、`#VALUE!`、`#REF!`、该有公式却没公式、公式说明被写成了公式、写死的派生合计、汇总明细不一致、不可能的箱规/数量数学、可见生成痕迹。有错误就报草稿或修好再交。
12. **给优先级行动并交接**。先解决准入/IP/税务阻断，再 HS/关税/清关，再履约。风险边界清楚后才用 `references/handoff-rules.md`。

### 强制决策闸门（Mandatory Decision Gates）

在建议 listing、商业发货、FBA/海外仓入仓、海外仓转仓、DDP/DAP 路线执行、或付费上线之前，按顺序检查：

1. **用户定义闸门**。严格按提示词的放行/持有/P0/P1。用户说 P0/P1 必须关完才发，就不许试发或分批发。**本仓库用户硬规则 A9：车标图形（整车厂品牌 emblem，如奔驰三叉星、BMW 圆标、丰田三椭圆）一旦出现在文案、图片、Fitment 卡、Listing 或发布建议中，本闸门即判 `NO-GO`——不得给可发布结论，必须移除/替换车标后重审；YMM/OE/"for Toyota Camry" 等适配文字不算车标，走既有商标证据审核，不在本闸门自动阻断。**
2. **产品与平台准入**。禁限售状态、认证覆盖、标签、宣称、IP 授权、危险品分类、平台后台审批、产品-文件匹配，必须对受影响 SKU/批次关闭。
3. **进口商与税务链**。IOR/EORI/VAT/GST/Sales Tax/Nexus/OSS/IOSS/Marketplace Facilitator 假设必须按路线和渠道分开算。平台仓、3PL、FBA、本地仓、直邮、独立站销售**不能塌成一个税务结论**。
4. **清关与估价**。HS、原产国、申报货值、发票、装箱单、Incoterms、进口 VAT/GST 基数、报关行/承运商要求、低价值进口规则，必须核验或明确标候选。
5. **危险品与履约**。电池/液体/粉末/化学品/磁体/加压/医疗/儿童等风险属性，需要 SKU/批次证据、承运商接收、平台仓审批（如适用）。
6. **文件与计算完整性**。任何生成的工作簿/报告里有未解决的公式错、总额不一致、箱规数学错、来源映射缺、叙述与文件决定不一致，交付物不能叫 final。

任一闸门不过，只在用户定义允许时输出 `HOLD` / `NO-GO` / `CONDITIONAL TEST`，并列出关闭证据、owner、核验路径。

### 车标门禁正反例（A9 用户硬规则）

判据只看"是否出现整车厂品牌**图形标识本身**"，不看是否出现品牌文字。

| 例 | 内容 | 判定 | 理由 |
| --- | --- | --- | --- |
| 阻断 | 主图/副图/Fitment 卡上出现奔驰三叉星、BMW 蓝白圆标、丰田三椭圆、福特蓝椭圆等图形 | `NO-GO`，移除/替换后重审 | 车标图形 = 用户硬阻断项 |
| 放行（过本闸门后再走既有商标审核） | 文案写 "fits Toyota Camry 2018"、OE 号 48610-06230、"replaces OEM 4861006230" | 不被本闸门自动阻断 | 这是 YMM/OE 适配文字，不是车标图形，不扩大化 |
| 阻断（信息不足） | 图片无法自动识别是否含车标（本技能无图像识别能力） | `needs_human_review`，不默认放行 | A9：图像无识别能力时保留人工复核 |
| 易误判（反例） | 因为写了品牌名 Toyota 就判 NO-GO | 错误 | 品牌文字 ≠ 车标图形 |
| 易误判（反例） | 同行 listing 主图里也有车标，所以我们也能用 | 错误 | 官方政策与同行行为都不豁免用户硬规则 |

规则边界：本门禁只阻断车标图形本身。控制臂、衬套等自有产品的工程图、白底产品照、我们自己已注册并用于自有 ASIN 的品牌 logo 不在此列。

### 输入规则（Input Rules）

- 目标国家/地区和平台是给具体合规、税务、进口、平台政策建议的必填项。缺了就给通用清单并问。
- 产品细节必填：商品名、材质、成分、功能、目标用户、电池/液体/粉末/食品/化妆品/医疗/儿童/电子等风险属性、品牌/IP 元素。
- HS/关税/清关任务要：原产国、目的国、产品描述、材质/用途、申报货值、币种、数量、最好有候选 HS 或供应商规格。
- 税务任务要：卖家主体、平台/独立站、发货地/仓位置、客户目的地、销量/单数、B2B/B2C、税号、平台是否代收代缴。
- 履约任务要：平台、履约方式、重量/尺寸、包装、库存量、售速、退货预期、危险品状态、目标服务水平。
- 中国进口任务要：中国进口商/收货人、贸易方式、原产国、发货国、SKU 级产品属性、候选 HS、成交方式、发票、装箱单、CCC/标准/标签状态、IP 授权链、目的地销售渠道。
- evidence-bound file 任务要输入文件清单和来源层级。聊天记录、旧草稿、供应商说法、报价在任务没显式指定为权威前都只是线索。
- **不许编官方规则、税率、HS 编码、关税率、平台审批状态、认证要求、IP 干净结论、账户状态、运费、交期**。

### 质量底线（Quality Bar）

一个好答案：

- 找出主导路径和跨路径依赖。
- 用最轻的清晰格式说出关键事实和缺失信息。
- 高风险建议前先给官方/一手核验路径。
- 用风险等级，清楚区分候选和已核验事实。
- 有 SKU 数、总件数、总货值、原产国数、发票总额、装箱单重量、批次成本、税、到岸成本、销售额、毛利时，全部对账。
- SKU 级证据状态分开记，可追溯到来源文件、位置、版本、日期。
- 叙述、Excel、CSV、Word 在每个关键数字和状态上一致。
- 给卖家能用的文件和后台证据清单。
- 除非用户给了官方证据，否则不给最终法律、税务、IP、清关、HS、关税、平台政策结论。
- 给优先级行动计划和交接边界。

避免：

- 没有官方证据就回答"能卖/不能卖/没税/没侵权/HS 就是 X"。
- 把 Accio、WorkBuddy、第三方工具、同行 listing、公开平台页当成政策权威。
- 不抽字段就把税务、IP、清关、物流混成泛泛建议。
- P0/P1 合规阻断没解决就建议发库存、FBA/海外仓、listing、广告。
- 把法律、税务、报关行、律师级建议当最终专业结论给。
- 任何明细-汇总对账没过还出漂亮最终答案。
- 没显式覆盖证据就把一个 SKU 的 UN38.3、SDS/MSDS、电池声明、CCC、授权、审批状态抄到另一个 SKU。
- 能用公式或共享计算模型保审计链时，在生成文件里写死派生合计。

### 回答风格（Response Style）

本技能和它的 references 是推理辅助，不是 few-shot 例子，也不是固定报告格式。普通 advisory 答案按请求比例给，不把通用风险章节、表格、模板塞进简单问题。

简单 advisory 通常覆盖：结论或建议姿态、关键原因/阻断、缺的证据或核验路径、下一步动作。

复杂多 SKU/多国/多渠道/高风险任务，只挑有用维度：任务理解与选定路径、关键字段与缺失信息、官方来源/核验路径、合规/税务/IP/准入/HS/清关/履约风险、所需文件与后台证据、优先级下一步与未解决交接风险。

evidence-bound file 模式，回答或交付物必须背：输入来源与版本清单、跨文件对账与差异跟踪、SKU 证据/状态推理、计算台账与控制总额校验。

交付前跑一次覆盖文字回答、Excel、CSV、Word（如存在）的内部一致性检查。只把最终校验结果报给用户，不暴露脚本、调试日志、修补痕迹。

### 交接规则（Handoff Rules）

- **A9 车标门禁随交接继承**：向 Listing/图片/Fitment 卡/广告/库存任何下游技能交接时，必须显式带一句"图片/文案/Fitment 卡不得含整车厂品牌图形标识；命中即 NO-GO，移除替换后重审；无图像识别能力时标 needs_human_review"。下游技能不得因未重新跑合规检查而放行车标素材。
- 产品机会、市场需求、同行选品、利润验证：本仓库无对应选品技能，输出"候选，需公司成本库校验"，不路由到外部技能名。
- Listing 标题、五点、PDP 优化、关键词、图片、本地化文案、宣称安全改写：`skills/amz-listing-audit/`、`skills/amz-listing-images/`；只传允许宣称、禁止宣称、所需标签/认证、IP 注意事项，**并附 A9 车标门禁**。
- PPC、竞价、匹配类型、ACOS/TACOS、广告组、站外增长：`skills/amz-ads-diagnose/`；只传产品准入与宣称边界，**素材不得含车标**。
- 断货/库存补货节奏：`skills/amz-stock-alert/`；只传履约路线与容量边界。
- TikTok 脚本、UGC、达人 brief、短视频、TTS/配音：本仓库无对应技能，只输出禁止宣称、内容限制、所需免责声明，不路由到外部技能名。
