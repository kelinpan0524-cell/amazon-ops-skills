# 竞品与跟卖监控

只盯同货架：同品类、同车型适配、同价格带的卖家。名单在 `config/competitors.json`，5–10 个 ASIN，宁少宁准。

**两种运行方式（2026-11-04 起）**：
- **自动**（推荐）：`scripts/run.py` 走卖家精灵 MCP 拉快照 + 与上次比对，只报变化；
- **人工**（MCP 不可用/额度紧）：按本文「人工巡检表」手抄，同样只报变化不报绝对值。

**都不抓亚马逊页面**（违反平台条款且一改版就失效）——自动模式用的是卖家精灵的采集数据。


## 交互协议（主动调用时：先问清，再执行）

本技能是**主动式**技能。被调用时不要直接闷头跑脚本：先核对下面的前置信息，
缺哪项就**用带选项的问题**一次问清（一次最多 3 个问题，能合并就合并），拿到答案再执行。

| 前置信息 | 为什么需要 | 选项 / 默认值 |
|---|---|---|
| 竞品 ASIN 清单 | 监控对象 | 必填；缺则询问并给出「按本店类目头部」候选 |
| 监控项 | 价格/评论/排名/跟卖 | 默认全部；频率默认每日 |

多轮对话规则：
1. 用户后续补充或修改口径时，以**最新一轮**为准，并复述确认关键参数（范围/对象/阈值）。
2. 信息齐全后先用一句话复述「我要用什么对象 + 什么时间窗 + 什么阈值 + 输出什么」，再动手。
3. 缺数据/缺密钥时直说并给替代路径，**不编数**；外部写操作（发消息、写外部表格、改广告）必须显式确认。
4. 用户只想快速要结果时，可直接采用上表默认值，但要在开头列出所用默认值。

## 用途

每周对名单里的 5–10 个同货架 ASIN 做一次比对，只记录相对变化（价格、评分、评论数、BSR、卖家数），
把"可能在打价格战/在测点击率/被跟卖"之类的信号写成一句判断。它回答"同行最近动了什么"，
不追求绝对值，不自动跟价、不代举报。

## 何时使用 / 不使用

**使用：**

- 每周五 17:00 例行巡检。
- 有人问"同行最近在干什么"。

**不使用：**

- 不批量抓页面/跑爬虫：违反平台条款且一改版就失效。
- 不盯整厂对手（中鼎、拓普等）：他们不是同货架竞争，只盯具体 ASIN。
- 不把竞品降价当必须跟：先看自己的盈亏线（`amz-ads-diagnose` / 成本结构）。
- 不用于输出精确的市场份额、绝对值排行——本来就不准。

## 最小输入

- `config/competitors.json` 里已填好的 ASIN 清单（品牌/品类/价格带/为什么盯）。**当前该文件是草稿，清单行还是【待补】占位**——见失败降级。
- 人工打开的前台页面（无痕窗口，避免个性化影响）。
- 可选：自己对应 SKU 的盈亏线/成本结构（判断要不要跟价时用，未校准前只作参考）。

没有清单就没有输入：脚本读 `config/competitors.json` 的 ASIN 清单，清单为空时停在 `needs_data`，不编竞品。

## 运行与输出（2026-11-04 升级：接了卖家精灵就不用手抄了）

**前置**：配好卖家精灵 MCP（`docs/DATA-SOURCES.md` 第 2 步），并在
`config/competitors.json` 里填好竞品 ASIN（5–10 个，宁少宁准）。

```bash
# 在仓库根目录执行；用 install_skills.py 软链安装的，把 skills/ 换成 ~/.agents/skills/ 下的实际路径
# 自动拉竞品快照 + 与上次快照对比（数据存 data/raw/competitor/，不进 git）
python3 skills/amz-competitor-watch/scripts/run.py
python3 skills/amz-competitor-watch/scripts/run.py --format text   # 群消息摘要
```

输出：`data/reports/competitor/<日期>_watch.html`——每 ASIN 一行（到手价/评分/评论数/BSR
及相对上次的变化），变化最大的 3 条置顶；有跟卖嫌疑或竞品断货时退出码 1。

**两种模式都支持**：
- **自动模式**（推荐）：卖家精灵 MCP 拉快照，脚本比对，人只看「变了什么」；
- **人工模式**（MCP 不可用/额度紧）：按下面的表手抄，同样只报变化不报绝对值。

```
| ASIN | 到手价变化 | 评分/评论数 | 主图换没换 | 有无上新变体 | 断货迹象 | 备注 |
```

派生与判断的区别：表里的"变化"是抄下的公开事实（现在由卖家精灵提供，标「估算」）；
"可能在打价格战/在测点击率"是候选信号，写进 `judgements/` 两周后回看对不对，而不是当场结论。

**清单在哪**：`config/competitors.json`。清单空着时脚本停在 `needs_data`，不编竞品。

## 失败降级

- **`config/competitors.json` 清单为空/仍是【待补】**：输出 `needs_data`——先由人填 5–10 个具体 ASIN（含品类/价格带/为什么盯），再开这条巡检；不得凭空编 ASIN 或变化。
- 人工没看前台页面：明确标 `needs_human_review`，不生成竞品结论。
- 某 ASIN 前台打不开/被风控：记"未取到"，不猜它的价格或排名。
- 看了但没有任何变化：报"0 项变化"，不强行找信号。
- 清单里连续三个月没有变化的 ASIN：按季度清换（`config/competitors.json` 规矩），不靠脚本自动删。

## 数据质量限制

- 数据是人工抄的前台快照，只做相对变化参考，不追求绝对值——优惠券经常改，标价不可信。
- 无痕窗口也不能完全消除个性化/地区差异；到手价以含券后的实际价为准。
- 没有成本结构/盈亏线时，"要不要跟价"无法判断，只能报竞品变化。
- 本技能不接触领星，不覆盖销量/利润侧数据。

## 人工确认边界

- 跟价、改自己 Listing/价格、发起举报、对外沟通，全部由人执行；本技能只发现变化、给建议，不自动跟价也不代举报。
- 每条判断写进 `judgements/`（带复核日，默认两周），到期由 `amz-calibration` 拉出来对账。
- 竞品页面或素材里若涉及车标/商标，只作观察记录，不据此给我们自己的发布结论；我们自己的车标硬阻断由 `amz-listing-audit` / `amz-listing-images` 守。

## 追溯与验证

## 高级规则

### Procedure

1. 打开 5–10 个 ASIN 的前台页（用无痕窗口，避免个性化影响）。
2. 只记有变化的三项：价格（算上优惠券的到手价）、评论数增量、主图/变体。
3. 变化里挑出"可能在打价格战"或"在测点击率"的信号，写一句判断。
4. 判断进 `judgements/`，两周后回看对不对。

### Pitfalls

- **别抓页面批量跑**：条款 + 稳定性双重风险。
- **别用标价**：只看到手价，优惠券经常改。
- **别盯整厂对手**：中鼎、拓普不是同货架竞争，盯具体 ASIN。
- **别把竞品降价当必须跟**：先看自己的盈亏线。
