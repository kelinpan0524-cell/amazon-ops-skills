# 评论监控

每天看自己 ASIN 有没有新评论，1-3 星单独挑出来。

## 为什么这件事值得单独一个技能

汽配类的差评比别的类目更有信息量：**「装不上」「尺寸不对」多半是 fitment 数据错了**，
不是客户挑剔。一条 1 星差评如果压着不看，后面会变成一批退货 + 退货率超标（官方收费线 9.1%）。
所以差评要当天看到，不能等周报。

## 用途

| 信号 | 判什么 | 级别 | 先做什么 |
| --- | --- | --- | --- |
| 新的 1-2 星 | 产品/fitment 可能有问题 | **要看** | 读内容判断是装不上、尺寸、还是物流损坏 |
| 新的 3 星 | 有不满但没到退货 | 看一眼 | 通常是"能用但不如预期"，看是不是描述不符 |
| 新的 4-5 星 | 正常 | 不用动 | — |

**只报「这次才有」的评论**：评论页每次拉回来都是同一批老评论，不去重就会天天报同样的差评，
人很快会无视这个告警（狼来了效应）。去重键是「日期 + 标题前 40 字」——评论没有稳定 id。

## 何时使用 / 不使用

**使用：**
- 每天跟跟卖监控一起跑（07:00，`config/automations.yaml` 的 `review-watch`）；
- 有人问"最近有没有人骂我们"。

**不使用：**
- 想分析评论里的产品改进点 → 用卖家精灵官方的「评论痛点分析助手」技能（它做 1-3 星语义归类，本技能只挑出来）；
- 想回复评论 → 那是 Seller Central 里人工做，本技能不写任何外部动作。

## 前置

`config/watchlist.json` 填自己的 ASIN（**与跟卖监控共用同一份名单**，都是自己的产品）。

**成本**：卖家精灵按次计费，每个 ASIN 每天 1 次（拉最近 20 条评论）。

## 怎么跑

```bash
# 在仓库根目录执行；用 install_skills.py 软链安装的，把 skills/ 换成 ~/.agents/skills/ 下的实际路径
# 每天拉最新评论并比对
python3 skills/amz-review-watch/scripts/run.py --fetch

# 不花额度，用已存快照重算
python3 skills/amz-review-watch/scripts/run.py

# 群消息摘要
python3 skills/amz-review-watch/scripts/run.py --format text
```

第一次跑只存快照、没有基准，会把现有评论全当"新"——这是预期行为，第二天起才只报增量。

## 输出

- `data/reports/review/<日期>_review.html`：新评论清单（差评排前面，1 星在最上）；
- `data/raw/review/<日期>.json`：当天快照（不进 git）；
- 退出码：`1` = 有新差评；`0` = 无差评；`2` = 快照不足/无数据。

## 口径与边界

1. **只看到卖家精灵采集到的那部分评论**（它有自己的覆盖率，不是亚马逊全量）；
2. **星级解析失败给 None 而不是 0**——0 会被误判成"零星差评"；
3. 评论没有稳定 id，用「日期 + 标题前 40 字」去重；同一人改标题会被当成新评论（很少见，可接受）；
4. **不做情感分析**：这个技能只按星级分档。要提炼产品改进点走官方「评论痛点分析助手」。
